# ALEPH T05 — AI Handoff

## 1. 프로젝트 소개

본 프로젝트는 기존 Card Studio를 기반으로 **AI 모델 간 작업 인수인계와 협업 과정**을 검증하는 프로젝트입니다.

모델 A(Gemini)가 먼저 편집 히스토리 시스템을 구현하고, 모델 B(ChatGPT)가 모델 A의 코드와 인수인계 문서를 전달받아 남은 기능을 완성하는 방식으로 진행합니다.

두 모델의 작업 시간, 사용자 요청 횟수, 고정 검사 결과를 기록하여 AI 간 인수인계의 정확성과 작업 연속성을 비교합니다.

| 프로젝트명   | ALEPH_T05_AI_Handoff                                                                                   |

| 모델 B    | ChatGPT                                                                                                |
| 구현 기능   | 편집 히스토리 시스템                                                                                            |
| 진행 방식   | A 모델 1차 구현 → 인수인계 → B 모델 이어서 구현                                                                        |

## 2. 구현 목표

기존 Card Studio에 편집 히스토리 시스템을 추가하여 사용자가 편집 작업을 기록하고 이전 상태로 복원할 수 있도록 합니다.

### 최종 구현 목표

1. 편집 작업 기록 자동 생성
2. Undo(실행 취소) 기능
3. Redo(다시 실행) 기능
4. 편집 히스토리 목록 표시
5. 기록 목록에서 특정 시점 선택 및 복원
6. 최대 20단계 편집 기록 제한
7. 과거 시점에서 새로운 편집 시 이후 Redo 기록 삭제
8. 복원 상태와 PNG 저장 결과 일치

기존 Card Studio의 텍스트 편집, 이미지 불러오기, 배경 설정, 템플릿 관리, PNG 저장 기능은 유지합니다.

## 3. AI 공통 사용 제한

모델 A와 모델 B에는 동일한 작업 제한을 적용합니다.

| 항목           | 모델 A(Gemini) | 모델 B(ChatGPT) |
| ------------ | ------------ | ------------- |
| 최대 작업 시간     | 50분          | 50분           |
| 최대 사용자 요청 횟수 | 5회           | 5회            |
| 고정 검사        | 10개          | 10개           |

작업 시간 또는 요청 횟수 중 하나라도 먼저 상한에 도달하면 해당 모델의 구현 작업을 중단합니다.

작업이 먼저 완료된 경우 실제 소요 시간과 요청 횟수를 기록합니다.

## 4. 공통 고정 검사 10개

모델 A와 모델 B 모두 동일한 검사 항목과 기대 결과를 기준으로 평가합니다.

| 검사 ID   | 검사 항목               | 기대 결과                                    |
| ------- | ------------------- | ---------------------------------------- |
| T05-S01 | 텍스트 편집 기록 생성        | 텍스트 변경 시 히스토리 목록에 기록이 1개 추가된다.           |
| T05-S02 | Undo 실행             | Undo 실행 시 직전 편집 상태로 복원된다.                |
| T05-S03 | Redo 실행             | Undo 이후 Redo를 실행하면 취소한 상태가 다시 적용된다.      |
| T05-S04 | 연속 Undo 3회          | 편집을 3회 진행한 뒤 Undo를 3회 실행하면 초기 상태로 복원된다.  |
| T05-S05 | 특정 시점 복원            | 기록 목록에서 특정 시점을 선택하면 해당 상태로 복원된다.         |
| T05-S06 | 배경색 변경 복원           | 배경색 변경 후 Undo 실행 시 이전 배경색으로 복원된다.        |
| T05-S07 | 텍스트 위치 복원           | 텍스트 이동 후 Undo 실행 시 이전 위치로 복원된다.          |
| T05-S08 | 새로운 편집 시 Redo 기록 삭제 | Undo 후 새로운 편집을 하면 이후 Redo 기록이 삭제된다.      |
| T05-S09 | 최대 20단계 기록 제한       | 25회 편집 후에도 Undo는 최대 20단계까지만 가능하다.        |
| T05-S10 | PNG 저장 결과 일치        | 이전 상태 복원 후 PNG 저장 시 미리보기와 동일한 이미지가 생성된다. |

### 검사 판정 기준

- **PASS:** 실제 실행 결과가 기대 결과와 일치한 경우
- **FAIL:** 실제 실행 결과가 기대 결과와 다른 경우
- **미검사:** 실행하지 않았거나 결과를 확인하지 못한 경우

검사하지 않은 기능을 PASS로 기록하지 않으며, 두 모델의 검사 결과를 동일한 기준으로 비교합니다.

## 5. 모델 A — Gemini

### 5.1 담당 작업 및 목표

모델 A의 목표는 기존 Card Studio의 기능을 유지하면서 편집 작업의 자동 기록, Undo/Redo 및 편집 기록 목록을 구현하는 것이었습니다.

### 5.2 모델 A 구현 상태 (첨부 인수인계 문서 기준)

- `script.js`: `undoStack`, `redoStack` 기반 `saveState()`, `undo()`, `redo()` 구현
- 키보드 단축키: `Ctrl+Z`, `Ctrl+Y`, `Ctrl+Shift+Z` 지원
- `getChangeDescription()`: 변경 사항에 따른 편집 기록 설명 자동 생성
- `renderHistoryLog()`: 편집 기록 목록 UI 렌더링
- 텍스트 수정, 스타일·비율 변경, 이미지 업로드·제거 등 주요 편집 동작의 기록 적재
- `index.html`: Undo/Redo 버튼 및 `#historyLogList` 영역
- `style.css`: 편집 기록 목록 스타일

위 내용은 **모델 A의 첨부 인수인계 문서에서 설명한 당시 상태**입니다. 이후 GitHub에 올라온 다른 버전의 구현 상태와 혼동하지 않습니다.

### 5.3 모델 A 작업 시간 및 요청 횟수

| 항목 | 결과 |
|---|---|
| 작업 시간 상한 | 50분 |
| 사용자 요청 횟수 상한 | 5회 |
| 기록된 경과 시간 | 34분 |

모델 A는 HTML/CSS/JavaScript의 초기 히스토리 시스템과 7개 항목으로 구성된 인수인계 문서를 제공했습니다. 기록 목록 클릭 복원과 최대 20개 제한은 모델 B에 전달된 후속 작업으로 기재되어 있습니다.

### 8.1 오류 수 산정 방법 (T05-C25)

- **오류 1회**는 공통 고정 검사 10개를 한 회차로 실행했을 때, **한 개 이상의 FAIL이 존재하는 회차**를 의미합니다. 한 회차에서 FAIL이 여러 건 발생하더라도 오류 수는 1회로 계산합니다.
- 현재 확인되는 **최종 고정 검사 회차는 각 대상별 1회**입니다. 대상 ①은 해당 회차에 FAIL 3건이 있어 **오류 1회**, 대상 ②는 FAIL 0건으로 **오류 0회**입니다.
- 이전 또는 추가 검사 회차의 실행 기록은 확인되지 않으므로 이 집계에 포함하지 않았습니다. 이후 다른 회차 기록이 확보되면 회차별로 다시 계산해야 합니다.
