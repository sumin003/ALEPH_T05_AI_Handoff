# ALEPH T05 — AI Handoff

## 1. 프로젝트 소개

본 프로젝트는 기존 Card Studio를 기반으로 **AI 모델 간 작업 인수인계와 협업 과정**을 검증하는 프로젝트입니다.

모델 A(Gemini)가 먼저 편집 히스토리 시스템을 구현하고, 모델 B(ChatGPT)가 모델 A의 코드와 인수인계 문서를 전달받아 남은 기능을 완성하는 방식으로 진행합니다.

두 모델의 작업 시간, 사용자 요청 횟수, 고정 검사 결과를 기록하여 AI 간 인수인계의 정확성과 작업 연속성을 비교합니다.

| 항목      | 내용                                                                                                     |
| ------- | ------------------------------------------------------------------------------------------------------ |
| 프로젝트명   | ALEPH_T05_AI_Handoff                                                                                   |

| 모델 B    | ChatGPT                                                                                                |
| 구현 기능   | 편집 히스토리 시스템                                                                                            |
| 진행 방식   | A 모델 1차 구현 → 인수인계 → B 모델 이어서 구현                                                                        |

## 2. 구현 목표

기존 Card Studio에 편집 히스토리 시스템을 추가하여 사용자가 편집 작업을 기록하고 이전 상태로 복원할 수 있도록 합니다.

### 최종 구현 목표

1. 편집 작업 기록 자동 생성
2. Undo(실행 취소) 기능
3. Redo(다시 실행) 기능
4. 편집 히스토리 목록 표시
5. 기록 목록에서 특정 시점 선택 및 복원
6. 최대 20단계 편집 기록 제한
7. 과거 시점에서 새로운 편집 시 이후 Redo 기록 삭제
8. 복원 상태와 PNG 저장 결과 일치

기존 Card Studio의 텍스트 편집, 이미지 불러오기, 배경 설정, 템플릿 관리, PNG 저장 기능은 유지합니다.

## 3. AI 공통 사용 제한

모델 A와 모델 B에는 동일한 작업 제한을 적용합니다.

| 항목           | 모델 A(Gemini) | 모델 B(ChatGPT) |
| ------------ | ------------ | ------------- |
| 최대 작업 시간     | 50분          | 50분           |
| 최대 사용자 요청 횟수 | 5회           | 5회            |
| 고정 검사        | 10개          | 10개           |

작업 시간 또는 요청 횟수 중 하나라도 먼저 상한에 도달하면 해당 모델의 구현 작업을 중단합니다.

작업이 먼저 완료된 경우 실제 소요 시간과 요청 횟수를 기록합니다.

## 4. 공통 고정 검사 10개

모델 A와 모델 B 모두 동일한 검사 항목과 기대 결과를 기준으로 평가합니다.

| 검사 ID   | 검사 항목               | 기대 결과                                    |
| ------- | ------------------- | ---------------------------------------- |
| T05-S01 | 텍스트 편집 기록 생성        | 텍스트 변경 시 히스토리 목록에 기록이 1개 추가된다.           |
| T05-S02 | Undo 실행             | Undo 실행 시 직전 편집 상태로 복원된다.                |
| T05-S03 | Redo 실행             | Undo 이후 Redo를 실행하면 취소한 상태가 다시 적용된다.      |
| T05-S04 | 연속 Undo 3회          | 편집을 3회 진행한 뒤 Undo를 3회 실행하면 초기 상태로 복원된다.  |
| T05-S05 | 특정 시점 복원            | 기록 목록에서 특정 시점을 선택하면 해당 상태로 복원된다.         |
| T05-S06 | 배경색 변경 복원           | 배경색 변경 후 Undo 실행 시 이전 배경색으로 복원된다.        |
| T05-S07 | 텍스트 위치 복원           | 텍스트 이동 후 Undo 실행 시 이전 위치로 복원된다.          |
| T05-S08 | 새로운 편집 시 Redo 기록 삭제 | Undo 후 새로운 편집을 하면 이후 Redo 기록이 삭제된다.      |
| T05-S09 | 최대 20단계 기록 제한       | 25회 편집 후에도 Undo는 최대 20단계까지만 가능하다.        |
| T05-S10 | PNG 저장 결과 일치        | 이전 상태 복원 후 PNG 저장 시 미리보기와 동일한 이미지가 생성된다. |

### 검사 판정 기준

- **PASS:** 실제 실행 결과가 기대 결과와 일치한 경우
- **FAIL:** 실제 실행 결과가 기대 결과와 다른 경우
- **미검사:** 실행하지 않았거나 결과를 확인하지 못한 경우

검사하지 않은 기능을 PASS로 기록하지 않으며, 두 모델의 검사 결과를 동일한 기준으로 비교합니다.

## 5. 모델 A — Gemini

### 5.1 담당 작업

모델 A는 Card Studio 편집 히스토리 시스템의 1차 구현을 담당했습니다.

초기 요청에서 다음 네 가지 기능을 우선 구현하도록 지정했습니다.

1. 편집 작업 기록 자동 생성
2. Undo 기능
3. Redo 기능
4. 편집 기록 목록 표시

다음 기능은 모델 B의 후속 작업 대상으로 지정했습니다.

1. 기록 목록에서 특정 시점 선택 및 복원
2. 최대 20단계 기록 제한
3. 과거 시점에서 새로운 편집 시 이후 기록 삭제

기존 Card Studio의 기능과 구조는 유지하는 것을 조건으로 했습니다.

### 5.2 모델 A 작업 내용

제공된 코드에서 확인되는 편집 히스토리 관련 구현은 다음과 같습니다.

| 파일           | 주요 작업                                   |
| ------------ | --------------------------------------- |
| `index.html` | Undo/Redo 버튼 및 편집 히스토리 패널 추가            |
| `style.css`  | 편집 히스토리 관련 화면 스타일                       |
| `script.js`  | 편집 상태 기록, Undo/Redo, 상태 복원 및 히스토리 목록 관리 |

첨부된 `script.js`에는 `saveState()`, `undo()`, `redo()`, `jumpToHistory()`, `applyFullState()` 등의 함수가 포함되어 있습니다.

키보드 단축키 `Ctrl+Z`, `Ctrl+Y`, `Ctrl+Shift+Z`도 연결되어 있습니다.

또한 첨부 코드에서는 `MAX_HISTORY = 20`으로 설정되어 있고, 과거 기록에서 새 편집을 수행하면 이후 기록을 제거하는 처리도 포함되어 있습니다.

이는 인수인계 문서에 기록된 일부 미구현 상태와 차이가 있으므로, 최종 동작 여부는 별도 실행 검증이 필요합니다.

### 5.3 모델 A 작업 시간 및 요청 횟수

Gemini 작업 기록 파일에 기재된 내용은 다음과 같습니다.

| 항목              | 기록                                       |
| --------------- | ---------------------------------------- |
| 시작 시각           | 2026.10.16 23:25                         |
| 종료 시각           | 2026.10.16 23:59                         |
| 시각상 경과 시간       | 34분                                      |
| 작업 기록상 실제 소요 시간 | 확인 불가                                    |
| 기록된 사용자 요청 횟수   | 1회                                       |
| 시간 상한           | 50분                                      |
| 요청 상한           | 5회                                       |
| 소스 식별 정보        | Card Studio v1.0 (History System 1차 구현본) |

시작·종료 시각의 차이는 34분이지만, 작업 기록 자체에는 실제 소요 시간이 '확인 불가'로 기재되어 있습니다.

사용자 요청 횟수는 첨부된 작업 기록에 기재된 1회이며, 전체 대화 기준 요청 횟수와 일치하는지는 추가 확인이 필요합니다.

### 5.5 검사 결과에 대한 주의 사항

Gemini의 검사 보고서와 작업 기록 사이에 결과 표기 차이가 있습니다.

- 검사 보고서: PASS 9건 / FAIL 0건 / 미검사 1건

- 인수인계 문서: PASS 9건 / 미검사 1건

본 README에서는 원본 보고서에 기재된 결과를 그대로 구분해 기록합니다.

따라서 Gemini가 기록한 PASS 9건을 공통 고정 검사 10개의 PASS 9건으로 간주하지 않습니다.

공통 고정 검사에 따른 모델 A의 실제 최종 점수는 재검증 전까지 확정하지 않습니다.

제공된 작업 결과물은 다음과 같습니다.

## 6. 모델 A → 모델 B 인수인계

모델 A는 다음 7개 항목으로 인수인계 문서를 작성했습니다.

### 6.1 목표

기존 Card Studio의 편집 기능을 유지하면서 안정적인 편집 히스토리 시스템을 완성합니다.

### 6.2 현재 상태

Gemini 인수인계 문서에는 Undo/Redo, 편집 기록 자동 생성, 기록 목록 표시가 구현된 것으로 기재되어 있습니다.

### 6.3 실행 방법

별도의 빌드 과정 없이 `index.html`, `style.css`, `script.js`를 같은 폴더에 두고 정적 웹 서버 또는 브라우저에서 실행합니다.

### 6.4 통과 검사

Gemini 인수인계 문서에는 TEST-01 ~ TEST-08, TEST-10의 PASS와 TEST-09의 미검사가 기록되어 있습니다.

### 6.5 남은 문제

Gemini 인수인계 문서에는 다음 문제가 기재되어 있습니다.

- 기록 목록 클릭 시 특정 시점으로 이동하는 기능
- 최대 기록 개수 30단계를 20단계로 변경하는 작업
- 기존 Card Studio 기능과의 통합 검증

단, 이번에 첨부한 코드에는 특정 시점 복원 함수와 20단계 제한이 이미 포함되어 있으므로, 모델 B는 인수인계 문서와 실제 코드의 차이를 먼저 확인해야 합니다.

### 6.6 다음 행동

모델 B는 인수인계 문서와 실제 소스 코드를 대조한 후 다음 작업을 수행합니다.

1. 현재 구현 상태를 확인합니다.
2. 인수인계 문서와 코드의 차이를 점검합니다.
3. 필요한 미완성 기능 및 오류를 수정합니다.
4. 기존 Card Studio와의 통합 동작을 확인합니다.
5. 공통 고정 검사 10개를 실행합니다.

### 6.7 건드리지 말 것

다음 기존 기능과 구조는 유지해야 합니다.

- PNG 저장
- 카드 비율 변경(1:1, 4:5, 9:16)
- 다중 텍스트 추가·삭제 및 편집
- 텍스트 드래그 및 위치 조정
- 배경색 및 그라데이션 설정
- IndexedDB 기반 사용자 템플릿
- Supabase Storage 기반 기본 템플릿
